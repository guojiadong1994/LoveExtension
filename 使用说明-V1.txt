LoveExtension V1.3.5：文件句柄版（图片和视频均不保存完整文件内容）

一、升级内容
- 保留 V1.3.4 的导航、名称修改、自动打开编辑页、原有悬浮球与手动一键上传。
- 原 content.js、style.css 完全没改。
- 右键配置窗口中，选择图片或视频改用 Chrome File System Access API 的 showOpenFilePicker。
- 使用 FileSystemFileHandle 引用本地原文件，仅将句柄和文件名、文件大小、类型、修改时间写到 IndexedDB；不会将 File/Blob 二进制素材写入数据库。
- 到广告编辑页后，使用句柄的 getFile() 取得原始文件的 File 对象，再交给旧版上传函数；不会提前复制几百 MB/GB 的素材。
- 文件读取许可失效时，在编辑页面出现“重新授权文件”按钮；原文件被移动、删除或修改时安全停止，不上传变化后的内容。
- 计划页加载时，会尽力删除旧版保存 File/Blob 副本的数据库 love-extension-workflow-media-v125；如果有旧版标签页占用，可能需要关闭标签页并重试。

二、安装步骤
1. Chrome 打开 chrome://extensions/，开启开发者模式。
2. 停用以前的 LoveExtension 版本，避免双份内容脚本。
3. 将 ZIP 解压，选择“加载已解压的扩展程序”，选中 LoveExtension 文件夹。
4. 刷新 ad.vivo.com.cn 广告计划页面。

三、使用步骤
1. 手动修改好某条广告计划名称并保存。
2. 在计划的蓝色标题上右键，核对或修改自动识别的名称。
3. 点击“选择图片 / 视频文件”，选择最多 10 张图片或最多 10 个视频（不混选）。支持“清除已选素材”；也可只改文案或仅同步名称。
4. 填写需要的应用名称、应用副标题，然后点击“开始自动处理”。
5. 扩展会同步广告组/广告名称、打开编辑页，并从原文件读取素材交给原有上传函数。
6. 如编辑页出现权限请求，请手动点击“重新授权文件”。完成后核查内容，再手动决定是否提交广告。

四、限制、隐私和故障排查
- 需要支持 File System Access API 的新版桌面 Chrome，以及用户点击发起文件选择。不支持时明确提示，不回退到大文件二进制复制方式。
- 文件句柄保存在 ad.vivo.com.cn 网站来源的 IndexedDB：同来源网站脚本理论上能访问句柄。请在信任该网站的前提下使用；任务完成、失败、停止会清理，过期句柄在后续进入计划页时清理。
- 原本的本地素材不会被修改；如果文件位置或内容发生变化，就需重新选择。
- 上传时仍会正常读取原文件内容并发送到 vivo，这不是“零数据读取”，只是“没有额外整份复制到浏览器数据库”。
- 页面跳转刷新导致上传中断时不会自动重试，以防重复上传。
- 自动化任务不会自动提交广告。

五、验证情况
- JavaScript 语法检查、句柄存储/恢复/权限与文件变更模拟测试已通过。
- 没有在实际 vivo 平台完成 V1.3.5 的完整浏览器端到端验证；建议先用 1 张小图片测试，再试视频。
