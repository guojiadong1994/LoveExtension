# LoveExtension V1.3.26 — 行业/产品级联菜单真实 DOM 修复

## 真实页面依据

来自 vivo GROUP 阶段手动展开菜单的只读检查结果：

- 可见弹层：`.ep-popper.ep-dropdown__popper`，内部有 `.mkt-cascader-panel`；
- 真正的选择器：`.ep-cascader-panel`，有**两个** `.ep-cascader-menu`；
- 一级行业：左列的 `li.ep-cascader-node[role="menuitem"] > .options-item > span`，如“金融-第三方支付”；
- 二级产品：右列相同节点结构，如“支付宝-便捷生活一点就好”；
- 旧版在自动执行时显示“匹配0项；候选：无”，可能是菜单没有展开，也可能是旧选项过滤条件过严。

## 修复

1. **固定使用两列逻辑**，分别从左列取行业、右列取产品，不再把不同 popper 的选项混在一起。
2. 增强弹层检测：按真实几何可见性和实际命中情况识别；不只因为存在 `aria-hidden` 就误判选项不可见。通过坐标命中检查避免点击被遮挡的菜单。
3. 展开逻辑不再只依赖第一个 `input`。在对应「行业/产品」表单字段内寻找多个实际可点击区域，通过 Chrome `Input.dispatchMouseEvent` 逐个尝试，**每次点击后立即检查菜单是否打开**，打开就不再多点。
4. 只在菜单已展开且目标选项**唯一**的情况下点击；点击二级产品后必须通过表单回显再次确认两个值。
5. 区分“菜单没展开”和“菜单展开但没有这个行业”的错误，展示点击坐标或左/右列候选，以便继续定位。

## 安全与边界

- 不修改旧版 `content.js`、`style.css`、`workflow/` 和其他批量创建文件；仅修改 `batch-create/debugger-cascader.js`、`manifest.json` 并附本说明。
- 操作被限制在当前批量任务的 vivo 创建广告工作标签页；调试连接会自动断开。
- 已通过基于用户提供 DOM 的本地 Chrome/CDP 模拟、默认逻辑/旧流程回归检查。
- **没有在登录状态的真实 vivo 网站验证**。如果仍失败，复制新版错误信息即可，尤其关注是否能识别弹层与左列候选。
- 建议使用新的测试广告名称，防止旧测试中已保存的计划被重复创建，首次验证关闭自动提交。
