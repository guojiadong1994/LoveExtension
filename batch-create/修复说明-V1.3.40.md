# V1.3.40 — 新批次启动时安全替换旧任务

- 右键只是打开配置，不发送停止指令。
- 新配置校验成功并点击「开始批量创建」后，替换包括 running/paused/failed/stopped/completed 在内的上一次任务。
- 前一任务状态不能再写入当前状态存储，避免迟到的后台回调把旧错误带回来。
- 尝试关闭扩展创建的旧 vivo 广告工作标签页，停止旧网页脚本；不关闭当前配置标签页，也不关闭已经转作其他用途的标签页。
- 清理旧任务在 IndexedDB 中的素材文件句柄引用，保留本机原文件与 vivo 已创建记录。
- 新任务参数校验失败不替换旧任务；保留全流程异常自动暂停、继续任务、主动停止、成功返回与刷新逻辑。

## 同版补充：任务框行为优化

- 移除右下角「人工接管」按钮及对应前端事件处理。自动失败走 FAIL → paused，人工修好后直接 RESUME。
- 任务框停止与右上角 × 使用相同的 STOP 后台确认逻辑；停止成功后立即隐藏。
- renderProgress 对 stopped 状态直接返回，不创建状态框，解决刷新页面或轮询后仍显示已停止提示的问题。
- 不涉及旧悬浮球、原一键上传和 legacy 工作流；最终提交确认弹窗的“暂不提交”仍然可以暂停。
